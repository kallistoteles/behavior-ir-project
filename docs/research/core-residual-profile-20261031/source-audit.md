## Diagnostic-cost controls

`validation-work` adds two full serializations solely to count bytes: `hash_document_json_bytes` in `hash_of` **and** `document_decode_json_bytes` in `decode`. The old script names only the former `diagnostic::document_byte_counter`. Give both distinct scopes (`diagnostic::hash_document_bytes`, `diagnostic::decode_document_bytes`) enclosing the complete existing counter closure. Their inclusive time belongs to instrumentation, not semantic serialization. Count-only fields such as `record_parse_bytes += text.len()` need no synthetic serialization. [Both counter sites](/tmp/behavior-ir-core-continuation-20261029/crates/behavior-store/src/documents.rs:226), [counter implementation](/tmp/behavior-ir-core-continuation-20261029/crates/behavior-core/src/eval/work.rs:56)

Report raw instrumented wall time, diagnostic scope totals, semantic scope calls/inclusive/exclusive time, and unexplained root residual. Parent inclusive scopes contain these diagnostics; exclusive time excludes only **immediate instrumented children**, not every descendant or all instrumentation overhead. Never add inclusive nested totals or subtract every ancestor's diagnostic allocation. A unique sum of diagnostic inclusive times is useful bookkeeping, but subtracting it does not recreate an uninstrumented execution: allocation/traversal can affect later state. Prefer a second explicitly identified diagnostic build with just these byte serializations disabled (call/row counts retained) when interpreting phase shares. Keep all primary timing binaries free of `validation-work`; exact byte/hash equality must cover diagnostic builds too. The old stack profiler also adds clocks, string labels and map aggregation; resulting spans are elapsed scopes, not CPU samples. [Profiler implementation](/tmp/behavior-ir-core-continuation-20261029/specs/031-scalable-execution-evidence/profiling/single-create-20261028/instrument.py:5)

## Minimal serialization discriminator

The previous driver times `evaluated.record.to_string()` immediately after successful commit. This is Store's returned `serde_json::Value`, cloned from the bundle; it is not typed Record07 serialization. Commit performs its own record text conversion, document materialization and clones before that window. C's decode/move change does not replace the later `Value` serializer. [Return clone](/tmp/behavior-ir-core-continuation-20261029/crates/behavior-store/src/store.rs:1900), [commit clone](/tmp/behavior-ir-core-continuation-20261029/crates/behavior-store/src/store.rs:2189), [reproduction text](/tmp/behavior-ir-core-continuation-20261029/crates/behavior-store/src/store.rs:3195), [pinned Value serializer](/home/kalle/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/serde_json-1.0.151/src/value/ser.rs:11)

Use N128 and N512, fresh processes, unchanged native evaluate/commit windows, and the same `Value::to_string()` API. For each compiled arm (at least prior baseline A and guarded C), retain:

1. **O1:** the original immediate post-commit first extra serialization, before parsing, output, or a new full-record equality walk. Retain its actual bytes.
2. **O2…O8:** repeated serialization of that same original Value; time each call separately. Stop each timer before byte comparison, artifact output or buffer destruction. Consume/compare each output after timing and drop it before the next call; freeze this rule for every sample.
3. Parse the retained O1 bytes into a fresh `serde_json::Value` outside timing, with exact equality checked after its first timed serialization. Retain **P1…P8** using the identical timed operation and output lifetime rule. Do not clone the original to create this control: the parse is the intentional independent materialization.
4. For a compact order control, fresh processes retain O1 first, then parse outside timing and alternate original/parsed repeat calls, reversing which object leads across repetitions. Compare this with the blocked sequence above; retain every call and process attempt. Parsing itself warms/traverses/allocates, so P1 is a fresh **object**, not a promise of cold hardware state.

Every emitted result must equal the frozen decision bytes, within and across arms. Record sample/process identity, arm/binary hash, N, sequence/order, object kind, call index and elapsed time. Summarize O1 separately, per-process repeat medians separately, and paired original/parsed differences; repeated calls are not independent fresh-process samples. The primary frozen campaign can retain its existing O1 measurement while this expanded driver is a separate diagnostic workload. Use the same parsed bytes in each arm to compare the serializer under a common logical input, without changing binaries between original and parsed calls. [Original measurement boundary](../core-typed-record-20261031/profile-driver.rs)

Interpretation is limited but useful: disappearance after O1 suggests an immediate operation-history effect; persistence only on the original Value motivates investigating representation/allocation history; persistence on fresh-parsed Values across binaries motivates checking compiled-code/layout or process/environment effects. None establishes cache misses, allocator contention, branch prediction, CPU frequency, or a particular compiler mechanism. A preallocated writer would test an additional allocation question, but changes the API and is outside this minimal experiment. `Value::Display` dispatches to serialization and the Value representation has no serialized-byte cache in this path. [Display implementation](/home/kalle/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/serde_json-1.0.151/src/value/mod.rs:197)

## Safe conclusions before new measurements

The prior campaign observed C/A standalone serialization median increases of **8.30% at N128** and **10.69% at N512**, plus a **1.16%** wider process increase at N128. These are retained regressions in the measured workload; neither five samples nor identical output establishes their cause or makes them noise. The source supports that C changes transient decoding, ownership moves and destruction during commit, while returned record bytes and the later serializer contract remain equal. Competing explanations include effects of those changed allocation/destruction histories, representation history, compiled-code differences, and run-to-run/process environment variation. They remain hypotheses. [Prior measurements](../core-typed-record-20261031/report.md), [secondary observations](../core-typed-record-20261031/secondary-analysis.json)

The next profile can identify remaining elapsed work in record construction, strict decode, common semantic checks, exact comparison, Value conversion, canonical checks/serialization, digest work and bundle clones. Primary speed claims still require uninstrumented measurements with retained attempts and exact bytes. It cannot establish a universal complexity change, a CPU-level bottleneck, or removal of the population-sized public record obligation from phase scopes alone.
