## B: deserialize the borrowed JSON into the same owned structs

`serde_json::from_value(raw.clone())` calls `T::deserialize(value)`. Replacing it with `serde::Deserialize::deserialize(raw)` changes the input deserializer from owned `Value` to `&Value`; `Record07`, `Record08`, all fields, and all later validation remain owned and unchanged. This removes the preliminary whole-tree clone; it does **not** eliminate owned strings, maps, vectors, or nested JSON materialization. The borrowed visitors still construct those outputs. [from_value](/home/kalle/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/serde_json-1.0.151/src/value/mod.rs:1037), [owned versus borrowed Value](/home/kalle/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/serde_json-1.0.151/src/value/de.rs:282), [owned String visitor](/home/kalle/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/serde_core-1.0.229/src/de/impls.rs:580)

The lockfile pins serde/serde_core/serde_derive **1.0.229** and serde_json **1.0.151**. In those local sources both deserializers use the same numeric dispatch, `Value::invalid_type`, null/Option behavior, sequence exhaustion checks, and derived missing/unknown-field rules. Their map iterators preserve the same order. Strings and map keys differ in visiting owned versus borrowed text, but the actual owned field visitors accept either. The schemas contain no custom field deserializers or borrowed output fields that require different behavior. Thus B has a strong source-based equivalence argument for these exact schemas and versions, including errors; this is not a blanket claim about every Deserialize implementation. ## Blocking counterexample for unrestricted C

Serde's ordinary derived struct deserializer accepts JSON **arrays** in field declaration order, even with `deny_unknown_fields`. Trailing defaulted fields can be omitted. CurrentTrace has thirteen fields; SemanticTrace has ten. The old projection strips child fields only from object trace entries, leaving arrays unchanged. [Value::deserialize_struct](/home/kalle/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/serde_json-1.0.151/src/value/de.rs:482), [derived sequence handling](/home/kalle/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/serde_derive-1.0.229/src/de.rs:451), [array exhaustion diagnostic](/home/kalle/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/serde_json-1.0.151/src/value/de.rs:192)

An otherwise valid legacy-language current record with `result:"INVALID_INPUT"`, no refused_request, and the following trace passes typed 08 and its pre-projection checks (`H` is a valid hash):

```text
[["precondition", H, {}, true, null, null, [], null, null, null, null]]
```

This has eleven elements: the last is subject=None. Raw null and child-field checks query object keys, so they see none on this array. The old projected parse returns `invalid length 11, expected fewer elements in array`; unconditional typed conversion discards the extra positional field and can accept the record. Arrays of length twelve or thirteen and child-phase arrays provide further variants. Even when a later common semantic error would reject, unconditional C changes the first error. These are source-derived counterexamples, to be executed by the parent experiment. [existing 08 raw-key checks](/tmp/behavior-ir-core-continuation-20261029/crates/behavior-core/src/record/typed_materialization_reference.rs:1)

**Required control:** after all existing 08 checks, use the exact old raw projection plus validate_record07 whenever any raw trace element is not an object. Otherwise use the typed move path. A blanket new rejection of arrays changes existing accepted forms; synthesizing a length error couples the code to Serde internals. The fallback also retains array-related first-error precedence without this coupling. Arrays in shared nested structs (action, reasons, failures, operands, rescale, derived, change, lifecycle) have identical types on both sides and remain valid inputs to the same later checks; do not silently normalize or tighten them.

## Error and ingress controls

All required non-Option fields retain their original wrong-type/null failures. Defaulted Vec fields accept omission, not explicit null; Option fields generally decode missing and null as None, but the existing targeted 08 raw null checks reject several explicit nulls. `facts:null` retains existing Option behavior. Raw checks on sequence-form action/reason/trace entries have existing shape-dependent behavior that the fallback must preserve. Unknown fields, integer u8/u32 bounds, missing required fields, malformed tagged obligations, and multi-defect inputs must compare **exact public code and message**, not only acceptance. Preserve the pre-validation order: typed 08 parse, profile pair, targeted nulls, language/archive pair, universe, refused-body evidence, action/reason nulls, all child/null checks, then common validation. [frozen validators](/tmp/behavior-ir-core-continuation-20261029/crates/behavior-core/src/record/typed_materialization_reference.rs:1)

Both candidates operate after the same initial strict lexical decode. Duplicate keys, floats including -0/exponents, out-of-range JSON integers, malformed JSON and trailing text must still fail there; ordinary whitespace and key ordering remain accepted. Tests constructed only from serde_json::Value cannot represent duplicate keys or original numeric spelling, so retain text ingress controls. Do not change raw JSON, output bytes, command occurrence/order, replay/reproduction, facts validation, archive/governance behavior, or other from_value sites while isolating these arms. [strict ingress](/tmp/behavior-ir-core-continuation-20261029/crates/behavior-core/src/canonical.rs:17), [profile selection](/tmp/behavior-ir-core-continuation-20261029/crates/behavior-core/src/record.rs:521)

Performance cannot be inferred from this audit; correctness passes do not by themselves justify production adoption.
